# The 40 shared questions, beside v0.12's files-alone baseline

This is the files-alone baseline for v0.12.1, on the grown scale eval set: v0.12's 40 questions, unchanged, plus the 6 new ones (#67). The command was:

```sh
deploy/home/run-evals.sh --agent claude --judge model --agent-model sonnet \
  --judge-model sonnet --corpus scale --configuration files-alone --runs 3
```

It ran in the VM at commit c860abf, whose tree is the same as `integration/v0.12.1` at e53a0ea, on 2026-10-20. Sonnet answers and judges, as in v0.12. The tool calls are recorded (#59).

- **Ingest:** 1,244 episodes, none quarantined.
- **All 46 questions:** correctness 0.88 (0.87 to 0.89), evidence recall 0.94 (0.93 to 0.94), citation validity 0.98 (0.97 to 0.99).
- **Cost:** $13.84 for the 3 runs. Per answer, the median was $0.089, 4 turns, and 11.5 s.

## Cited episodes opened

On all 46 questions, the report says sessions opened 0.04 of the episodes they cited. That figure undercounts. Sessions mostly read episodes in Bash loops, such as `for f in $(grep -rl …); do python3 -c "…json.load(open('$f'))…"; done`, so the file names exist only in a shell variable, and the check in #59 can't match them to cited episodes. Don't read this figure as "the assistant cites without reading". It shouldn't be compared across configurations until the check can see reads like these.

#78 fixed the check: an episode now counts as opened when its contents reach the session through any tool's output, not when its file is named. These runs can't be recomputed with it, because `results.json` records what each tool call was given but not what it returned, and a Bash loop's output is the only record of which episodes it printed. The 0.04 above stands as recorded. To compare the share across configurations, run files alone again with the fixed check.
